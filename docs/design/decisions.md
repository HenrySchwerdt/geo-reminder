# Design decisions

## D1 — Visual direction: “Liquid Glass Calm” (A)
Explored on the **Directions** page with the same Today screen and data:

| | A · Liquid Glass Calm ✅ | B · Liquid Glass Vivid | C · Flat Minimal |
|---|---|---|---|
| Material | Glass only on floating controls | Glass everywhere | None |
| Canvas | Warm neutral #F4F2EC | Saturated gradient | System grey |
| Legibility of numbers | Excellent | Fails contrast on parts of the cards | Good |
| Feels like iOS 26 | Yes | Demo-like | Dated |
| Calm / trust | High | Low | Medium, anonymous |

A follows Apple's Liquid Glass guidance (glass belongs to the navigation layer above content) and matches the
best references in `research.md` (warm off-white canvases, floating capsule tab bars, a single accent). B was
rejected because translucent content competes with the timer and fails contrast; C because it looks pre-2025
and has no hierarchy between controls and content.

## D2 — Four tabs, Today first
Today / Calendar / Insights / Settings. Settings is a tab rather than a gear button because workplaces,
pattern and reminders are visited more than typical settings during the first weeks. Insights is kept separate
from Calendar so history (precise, editable) and summaries (approximate, read-only) don't mix.

## D3 — Reminders ask, they never record
Geofence events only *suggest* a time. Recording without confirmation would create silent wrong data, which is
worse than a missed reminder. Users can later opt into “auto clock-in after 10 min” (not in M1).

## D4 — The detected time is the default answer
iOS region events are late by seconds to minutes. Offering “Clock in at 08:44 (arrived)” vs “now” makes a late
notification harmless and removes most corrections.

## D5 — Day ribbon instead of a ring on iPhone
A ring shows progress but hides *when* work and breaks happened, which is exactly what users need when
correcting. The ribbon scales from a 361-pt card to an 8-pt watch complication. Rings are used only where space is
round (watch, circular complications, month total).

## D6 — Corrections are append-only
Edits create events; the original stays visible in History (screen 7). Deleting offers Undo (32). Incomplete days
are excluded from the balance until fixed, so the overtime number is never silently wrong.

## D7 — Watch is for state changes, not editing
Small screen, wrist-down use. Corrections stay on iPhone; the watch shows state, time, progress and one or two
actions.

## D8 — Calendar shows hours, not dots
Each day cell carries its total (e.g. 8.5) so the month answers “did I do my hours?” without tapping.
Missing check-outs are red with “!” because they block the balance.

## D9 — Icons are stand-ins
Phosphor glyphs are drawn because SF Symbols cannot be redistributed; the code uses SF Symbols (mapping in
`design-system.md`).

## D10 — Designs are code
The FigCraft document is generated by `design/figcraft/src/build.py`, so the design system and every screen
are reproducible, reviewable in diffs and consistent by construction. Hand edits in FigCraft are possible, but
should be ported back to the generator or they will be overwritten on the next build.

## D11 — Logo: a pin that drops onto the day
A location pin lands on the start of a 300° day arc: arrival (geofence) starts the working day, which then fills
up. It connects the two ideas the product is built on — place and time — and avoids the stopwatch cliché of time
trackers. The default icon uses the warm paper of the app canvas (it stands out among the many dark-green and blue
utility icons); dark, clear (Liquid Glass), tinted and a green alternate cover iOS 26's icon appearances. The arc
uses the same stroke logic as the watch ring and widget gauges, so icon, complications and Live Activity read as one
system. Checked down to 20 px (Brand page). A first version (an arc starting at an amber dot) was dropped: it read as
a loading spinner.

## D12 — Watch and widgets redesigned around state colour
Watch screens use a full-bleed state glow (green working, amber break), one large progress ring with a white “now”
knob, and corner buttons — following watchOS conventions instead of shrinking the phone layout. Widgets lead with the
number, carry the mark + state label at the top and always end with the day timeline, so every size reads the same
way: *state → time → day*.
